# Maintenance Team Member - User Stories

> Each story has an ID that is referenced from the [implementation plan](./implementation_plan.md).

* <a id="mnt-01"></a>**[MNT-01] As a maintenance team member**, I want to receive clearly assigned tasks with location and description details so that I know exactly where to go and what needs repairing.

* <a id="mnt-02"></a>**[MNT-02] As a maintenance team member**, I want to receive an in-app dashboard notification when a task is assigned to my team so that I can start without delay.

* <a id="mnt-03"></a>**[MNT-03] As a maintenance team member**, I want to upload photographic evidence or a completion report so that I can provide proof that the repair was executed successfully.

* <a id="mnt-04"></a>**[MNT-04] As a maintenance team member**, I want to update the task status to "Completed" so that the ticket moves to "Verifying" and the administration knows my part of the job is finished and awaiting their confirmation.

* <a id="mnt-05"></a>**[MNT-05] As a maintenance team member**, I want to see and be notified in-app when the administrator rejects my proof, together with the rejection note, so that I know what to fix and can re-upload proof and mark the task "Completed" again.

> Note: Maintenance teams have no blocker-reporting feature. The only task actions are uploading proof and marking the task "Completed".
